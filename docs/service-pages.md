# 어썸·틸드 서비스 소개 페이지

제공된 기획서·브랜드 가이드·화면 디자인 HTML을 바탕으로 `/awesome/`, `/tilde/`를 구현했습니다. 두 서비스는 출시 준비 중이며, 소개 화면의 인물·일정·활동·회원 수는 디자인 예시입니다. 실제 가입·인증·매칭·결제는 실행하지 않습니다.

## 브랜드와 콘텐츠 기준

| 서비스 | 제공 자료                                                                                                             | 페이지 구성                                              |
| ------ | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 어썸   | `제품 기획서 초안(기능명세, 화면정의).html`, `어썸_화면디자인_정의서_초안.html`, `어썸, 가까움에서 피어나는 인연.png` | 네이비·골드, 확인된 프로필, 편지, 상호 동의, 만남 초대장 |
| 틸드   | `브랜드 가이드.html`, `서비스 기획서.html`, `screens/`, `brand-assets/`, `design-assets/photography/`                 | 올리브·오트, 두 사람의 대화, 함께하는 시간, 동아리       |

확정되지 않은 심사 가격·자산 기준·운영 수치나 사업 실적은 홍보 문구로 사용하지 않았습니다. 자료에 나온 임시 법인명을 현재 회사명으로 사용하지 않았으며, 공통 사이트의 JAVE 표기를 유지합니다.

[카카오 홈페이지](https://www.kakaocorp.com/page/)는 큰 비주얼과 여백, 순차적인 스크롤 스토리텔링의 참고로 사용했습니다. 로고·사진·문구는 카카오에서 가져오지 않았습니다.

## 현재 틸드 페이지 구성

`src/app/tilde/page.tsx`는 기존 `TildeHero` 다음에 `TildeConversation`, `TildeToday`, `TildeClubs`를 순서대로 조합합니다. 세 섹션은 `src/app/tilde/_components/stories/`에 각각 분리하고, 첫 갤러리는 `ConversationGallery.tsx`, 오늘의 갤러리는 `TodayGallery.tsx`, 동아리의 갤러리는 `ClubsGallery.tsx`가 담당합니다. 이 라우트 안에서 `StoryCopy.tsx`와 `StoryPhoto.tsx`를 함께 사용합니다. 문구와 사진 슬롯 24개(13·6·5장)는 `src/app/tilde/_data/stories.ts`, 첫 갤러리 사진별 상대 위치·크기·비율은 `src/app/tilde/_data/conversation-gallery.ts`에서 관리합니다. 모임의 배치·사진 선택은 `_data/today-gallery.ts`, 동아리는 `_data/clubs-gallery.ts`에서 관리하며 `ClubsGalleryPhoto.tsx`가 개별 동아리 사진의 위치·비율·등장 효과를 조합합니다.

| 순서 | 내용                        | 사진 영역과 배치                                                   | 섹션 ID             |
| ---- | --------------------------- | ------------------------------------------------------------------ | ------------------- |
| 1    | 조금 더 함께 있고 싶은 사람 | 가로 폭을 넓게 쓰는 13장 벽면 갤러리와 오른쪽 안쪽 문구            | `tilde-connections` |
| 2    | 오늘 가볍게 함께하는 시간   | 중앙 세로형, 크기가 다른 주변 네 장, 위쪽 작은 가로형의 6장 갤러리 | `tilde-today`       |
| 3    | 꾸준히 이어지는 동아리      | 왼쪽 네 장 사진 묶음과 오른쪽 상단 문구·하단 가로 프레임           | `tilde-clubs`       |

첫 갤러리는 화면 가로 폭을 넓게 사용하면서 사진 크기를 키우고 간격을 좁힌 13장 벽면 구성입니다. 위쪽 작은 사진은 아래쪽 위치를 유지하면서 폭을 줄였고, 오른쪽 위 가로 사진 세 장과 그 아래 가로 사진은 각각 다른 너비와 높이를 사용합니다. 아래쪽 가운데 `conversationLaugh`는 3:4 세로형이며, 캔버스 높이에 사진 전체가 포함됩니다. `lg` 이상에서는 `ConversationGallery`가 배치 데이터의 상대 좌표와 각 사진의 비율을 사용합니다. “조금 더, 같이 있고 싶은 사람.” 제목과 “헤어지기 아쉬운 대화, 돌아오는 길에도 떠오르는 웃음.” 설명은 오른쪽 위 사진들 아래의 갤러리 안쪽에 놓습니다. 문구는 일반 그리드 항목으로 높이에 참여하므로 길어지면 섹션이 자연스럽게 늘어나며 사진 최하단에 강제로 맞추지 않습니다.

첫 갤러리는 1024px 이상에서 기존 13장 벽면 배치를 유지합니다. 768~1023px에서는 9장·3열, 480~767px에서는 7장·2열, 479px 이하에서는 사용자가 선택한 1·3·4·7번 사진만 표시하고 10번 책방 사진은 숨깁니다. 왼쪽 열에는 1·3번, 오른쪽 열에는 4·7번을 놓고 오른쪽 열을 살짝 아래로 내립니다. 해변 사진 7번은 모든 화면에서 긴 3:4 세로형을 유지합니다. 7장 구성은 2·10·13번, 9장 구성은 여기에 6·9번을 추가합니다. 구간별 열 구성은 `conversation-gallery.ts`의 `conversationGallerySelections`에서 관리합니다. `_lib/create-gallery-selection.ts`가 표시할 슬롯만 고르고 `_lib/create-gallery-columns.ts`로 좌표와 캔버스 높이를 계산한 뒤 슬롯 번호에 연결합니다. 숨긴 사진의 자리를 남기지 않으며, 1024px 미만에서는 각 열의 시작 높이를 엇갈리게 해 기존 분위기를 유지합니다. 사진 비율은 16:9·3:4를 유지하고 원본을 늘이지 않습니다. 계산은 서버에서 수행하며 13개 사진을 한 번씩만 렌더링합니다. CSS 브레이크포인트로 표시 여부·좌표·프레임과 캔버스 비율을 함께 변경하므로 창 크기 변경용 스크립트나 중복 DOM이 필요하지 않습니다. 문구는 갤러리 아래에 이어지고, `lg` 이상에서는 기존 위치를 유지합니다.

오늘 섹션은 별도 배경색 없이 넓은 화면에서 왼쪽 문구·오른쪽 사진 구성을 유지하고, 사진 쪽에 더 넓은 가로 공간을 배분합니다. 문구는 갤러리 본체의 위쪽에 맞추며, 사진 묶음이 문구보다 아래까지 길어져도 섹션 높이가 자연스럽게 늘어납니다. `TodayGallery`의 중앙 `todayGroup`은 3:4 세로형이며, 왼쪽에는 16:9 `todayWalk`·`todayCoffee`, 오른쪽에는 16:9 `todaySunset`과 3:4 `todayLaugh`를 쌓습니다. 주변 네 사진은 서로 다른 너비를 사용합니다. 왼쪽 아래 사진은 작게 줄여 오른쪽에 맞추고, 오른쪽 아래 사진은 더 좁은 세로형으로 두어 다른 사진보다 아래까지 내려옵니다. 작은 16:9 `todayDetail`은 중앙 왼쪽 위에 두고 오른쪽 사진 묶음은 조금 낮춰, 여섯 장을 좁은 간격으로 모읍니다. 사진은 기울이거나 겹치지 않으며 각자 화면에 진입할 때 나타납니다. 1024px 미만에서는 문구 아래에 큰 사진 두 열을 두고 오른쪽 열을 낮춰 시작합니다. 왼쪽은 17번 세로형 다음에 15번 가로형을 두며, 768~1023px의 오른쪽은 18번 가로형·19번 세로형 순서로 배치하고 16번은 숨겨 총 네 장을 표시합니다. 열의 시작점과 사진 순서를 달리해 중간 사진 경계가 같은 높이에 맞지 않도록 합니다.

동아리 섹션은 1024px 이상에서 12열 그리드를 사용합니다. 왼쪽 7열에는 20·21·22·23번 사진 네 장을 두 행에 걸쳐 모으고, 문구는 오른쪽 상단의 8~12열에 배치합니다. 더 넓은 화면에서도 같은 열을 사용하며, 문구 왼쪽 안쪽 여백을 `clamp(3rem, 7vw, 8.5rem)`으로 지정해 문구 묶음을 오른쪽으로 옮깁니다. 그리드의 가로 간격은 16px, 세로 간격은 20px로 줄여 사진과 문구를 가깝게 모읍니다. 24번 모닥불 사진은 16:9 가로형으로 오른쪽 5열의 두 번째 행에 독립적으로 배치하되, 해당 영역 너비의 82%로 줄여 왼쪽에 맞춥니다. 22번과 겹치지 않도록 추가 가로 이동은 적용하지 않습니다. `ClubsGallery`는 좁은 화면에서 하나의 상대 배치 캔버스로 동작하고, 데스크톱에서는 `contents`로 전환해 왼쪽 사진 묶음과 24번 프레임을 섹션 그리드에 연결합니다. 왼쪽 네 장의 상대 좌표는 `_data/clubs-gallery.ts`에서 관리하며 캔버스 너비는 714 단위입니다. 22번 생일 사진을 상단 중앙에 크게 두고 원본 비율 1122:1402를 유지해 얼굴과 케이크가 모두 보이도록 합니다. 각 사진의 `(x, y, 너비)`는 22번 `(380, 0, 334)`, 그 아래 너비를 키운 20번 `(364, 438, 350)`, 왼쪽 21번 `(144, 68, 218)`, 보조 23번 `(100, 382, 236)`으로 간격을 좁혀 엇갈리게 배치합니다. 캔버스 높이는 네 사진 하단의 최댓값으로 계산합니다. 데스크톱에서만 20번은 -0.6도, 21번은 -1.1도, 22번은 +0.4도, 23번은 -0.7도, 24번은 +0.5도 기울입니다. 기울기는 바깥 프레임에 적용하고 개별 등장 효과는 안쪽 `TildeReveal`에 유지합니다. 24번은 데스크톱에서 절대 좌표 대신 일반 그리드 흐름에 참여합니다. 전체 다섯 프레임은 세로형 두 장과 가로형 세 장이며, 각 사진과 문구는 개별 `TildeReveal`을 유지합니다. 1024px 미만에서는 왼쪽 위에 가로형 20번 골프 단체 셀카를 놓고, 그 아래에 21번 세로 프레임을 배치합니다. 오른쪽은 22번 세로 프레임 다음에 24번 가로형 모닥불 사진을 둡니다. 같은 열의 두 사진은 너비와 좌우 끝선을 맞추고, 22번 생일 사진이 있는 오른쪽 열이 먼저 시작해 사진 경계가 엇갈리게 이어집니다. `_data/clubs-gallery.ts`의 사진별 `narrow` 좌표로 너비 1000 단위의 `narrowLayout`을 계산하고, `phone`·`compact`·`tablet`이 같은 배치를 사용합니다. 왼쪽 20·21번은 `x=0`, 너비 470을 공유하고 각각 `y=60`, `y=354`에 놓습니다. 오른쪽 22·24번은 `x=522`, 너비 454를 공유하고 각각 `y=0`, `y=597`에 놓습니다. 각 비율에서 구한 사진 하단의 최댓값으로 캔버스 높이를 계산합니다. 모든 좁은 구간은 같은 네 장을 표시하고 23번은 숨깁니다. 전폭 사진과 기울기는 적용하지 않습니다. `_lib/prepend-gallery-feature.ts`는 이전 전폭 배치 구현을 보관한 파일이며 현재 페이지에서는 사용하지 않습니다. 숨긴 슬롯의 빈자리가 남거나 다음 섹션과 겹치지 않으며, 각 사진은 하나의 DOM에서 화면 크기에 맞는 위치로 전환합니다.

모임·동아리의 반응형 표시 기준은 다음과 같습니다. 슬롯 번호는 화면 크기가 바뀌어도 유지합니다.

| 화면 너비   | 오늘 같이 할까요   | 동아리             |
| ----------- | ------------------ | ------------------ |
| 1024px 이상 | 14~19번, 6장       | 20~24번, 5장       |
| 768~1023px  | 15·17·18·19번, 4장 | 20·21·22·24번, 4장 |
| 480~767px   | 15·17·18·19번, 4장 | 20·21·22·24번, 4장 |
| 479px 이하  | 15·17·19번, 3장    | 20·21·22·24번, 4장 |

동아리 22번은 모든 구간에서 원본 비율 1122:1402로 표시하며, 23번은 1024px 미만에서 숨깁니다. 오늘의 골프 사진 19번은 모든 구간에서 3:4로, 동아리의 골프 모임 단체 셀카 20번은 모든 구간에서 16:9로 표시합니다. 24번 모닥불 사진은 모든 구간에서 16:9로 표시하며 중앙 번호와 장식 테두리를 숨깁니다. 각 사진의 개별 등장 효과와 사진 연결 시 번호·테두리를 숨기는 동작은 유지합니다.

첫 갤러리 1~13번에는 제공된 원본 PNG를 연결하고 장면에 맞는 `alt`를 제공합니다. 오늘 14번에는 야외 코트에서 테니스를 치는 여성의 16:9 사진을, 15번에는 원목 벽 실내에서 카드를 펼쳐 든 여성의 16:9 사진을, 16번에는 야외 트랙을 달리는 여성의 16:9 사진을, 17번에는 야외에서 카메라를 든 여성의 원본 3:4 사진을, 18번에는 공원에서 골든리트리버와 함께 있는 남성의 16:9 사진을, 19번에는 네이비색 선바이저와 흰 폴로 셔츠를 입고 골프채를 든 채 브이 사인을 하는 여성의 원본 3:4 사진을, 동아리 20번에는 골프 모임 단체 셀카를, 21번에는 야간 풋살 사진을, 22번에는 생일 케이크 앞 다섯 친구의 단체 사진을, 23번에는 회색 트레이닝복을 입은 다섯 친구의 연습실 거울 사진을, 24번에는 모닥불을 둘러앉은 친구들 사진을 연결했습니다. 현재 24개 슬롯 모두 사진이 연결되어 빈 슬롯은 없습니다. 슬롯은 16:9 또는 3:4 비율과 둥근 모서리를 유지하되, 22번 생일 사진만 원본 비율 1122:1402를 사용합니다. `StoryPhoto`는 사진이 연결되면 번호·흰 테두리·외곽선·그림자를 숨기고 이미지를 표시하며, `src`가 없는 슬롯을 사용할 경우에는 장식 테두리와 중앙 번호를 표시합니다. 이미지 생성·원본 수정·재압축은 하지 않았습니다.

첫 갤러리는 1~13번, 오늘은 14~19번, 동아리는 20~24번입니다. 사진이 채워져 화면의 번호는 숨기지만 데이터의 `slotNumber`는 유지합니다. 배치 변경으로 번호를 다시 매기지 않습니다.

모바일 이미지 길게 누르기 메뉴는 전역 `img`·`picture`의 `pointer-events: none`과 `-webkit-touch-callout: none`으로 제한합니다. 사진이 있는 `StoryPhoto`는 `data-image-protected`와 투명한 가상 요소를 사용해 이미지 대신 액자 영역이 입력을 받도록 하며, `ImageInteractionGuard`는 이 보호 영역과 이미지를 포함한 링크의 `contextmenu`·`dragstart`도 취소합니다. 이미지의 `alt`와 원본 표시, 링크의 일반 클릭은 유지합니다. `touchstart`·`touchmove` 취소나 `touch-action: none`은 사용하지 않아 스크롤과 핀치 확대를 막지 않습니다. 이는 브라우저의 일반 저장 메뉴를 제한하는 것으로, 화면 캡처나 원본 파일 접근을 완전히 차단하는 기능은 아닙니다.

이전 카드·테니스·휴대폰 앱 시안·ON/OFF 미리보기·활동 스크롤 장면과 기존 `ServiceCta`는 현재 틸드 페이지에 표시하지 않습니다. 관련 컴포넌트 파일과 원본 자산은 보관하며, 어썸에서 사용하는 공통 컴포넌트는 그대로 유지합니다. 이전 카드와 테니스 섹션의 미리보기 이동 링크도 함께 렌더링하지 않습니다. 첫 섹션은 기존 `tilde-connections` ID를 이어받습니다.

틸드 영상 아래의 소개는 “TILDE | 모든 만남이 시작 되는 곳” 문구, “취향이 닮아, 일상이 이어지다.” 제목, 사용자가 지정한 세 줄 설명을 그대로 유지합니다. 소개 문구의 왼쪽 뒤에는 세이지 그린을 20% 불투명도로 채운 타원을 왼쪽 위에서 오른쪽 아래로 기울여 배치합니다. 화면 크기에 맞춰 장식의 크기를 조절하며, 화면 낭독기와 포인터 입력에서는 제외합니다. 소개 본문과 첫 갤러리 영역 사이의 여백은 모바일 96px, `sm` 이상 144px, `lg` 이상 192px입니다. 첫 이야기와 오늘 섹션 사이의 합산 여백은 각각 240px·304px·432px이며, 오늘과 동아리 섹션 사이는 208px·288px·400px입니다. 영상 재생, 공통 메뉴와 공통 푸터에는 변경이 없습니다.

각 이야기에는 기존 사진 자리표시자의 연한 색을 재사용한 반투명 타원을 추가합니다. 첫 제목의 “같이” 뒤에는 베이지, 오늘 설명 둘째 줄의 “시간이” 뒤에는 작은 청회색 타원, 동아리 상단 문구의 마지막 “동아리” 뒤에는 모래색을 둡니다. 오늘 타원의 불투명도는 40%입니다. `StoryAccentText.tsx`는 지정 단어만 감싸고 타원을 절대 배치하며, `StoryCopy`가 적용할 문구 영역을 선택합니다. 설정은 `stories.ts`, 타입은 `_types/story-copy.ts`에서 관리합니다. 타원은 `aria-hidden`과 `pointer-events-none`으로 처리하고 기존 `TildeReveal` 안에서 문구와 함께 나타납니다. 원래 소개의 세이지 타원은 유지합니다.

`TildeHero`의 영상 아래 소개 영역은 틸드 전용 `TildeReveal`로 감싸 문구와 타원이 함께 나타나게 합니다. 소개 텍스트와 타원 배치는 유지합니다. 각 이야기의 `StoryCopy`와 `StoryPhoto`도 개별 `TildeReveal`로 감싸므로 문구 묶음과 사진이 각자의 화면 진입 시점에 나타납니다. 약 1초짜리 투명도·세로 이동 전환을 사용하고, 일부 문구와 사진에는 짧은 지연을 둡니다. 첫 갤러리는 `conversation-gallery.ts`의 액자별 `revealDelay`로 0~480ms의 지연을 지정해 같은 높이의 사진도 각기 다른 타이밍에 나타납니다. 각 액자의 화면 진입 감지와 동작 줄이기 설정은 유지합니다.

`src/app/tilde/_components/motion/TildeReveal.tsx`는 공통 `ScrollReveal`의 진입 감지와 접근성 처리를 재사용하는 라우트 전용 어댑터입니다. Tailwind 4의 세로 이동에 쓰이는 CSS `translate`를 전환 대상에 추가하고, 동작 줄이기 설정에서는 전환을 끕니다. 공통 `ScrollReveal` 자체는 수정하지 않아 어썸의 기존 동작을 유지합니다.

## 스크롤 효과와 접근성

- 틸드 첫 화면은 MYBOX의 새 1~16번 순서로 편집한 약 38.17초 영상을 소리 없이 자동 반복 재생합니다. 데이트 → 책 읽고 웃기 → 도서 동아리 → 보드게임 → 도예 → 소개팅 → 꽃밭 → 구름 → 테니스 → 농구 → 축구 → 커플 러닝 → 맥주 모임 → 모임 → 물결 → 바닷가 순서입니다. 마지막 바닷가 6초가 끝나면 처음으로 돌아갑니다. 전환 효과·색 보정·속도 변경은 추가하지 않았으며 스크롤 위치는 재생 시간에 영향을 주지 않습니다.
- 1·3·5·6·10·11·16번은 전체 내용을 유지합니다. 2번 1.2초, 4번 1.3초, 7번 1.3초, 8번 1.8초, 9번 1.3초, 12번 1.5초, 13번 3.1초, 14번 2초, 15번 3초로 맞췄습니다. 24fps 원본을 30fps로 정렬하며 전체 사용 장면의 마지막 프레임이 빠지지 않도록 필요한 프레임을 반복합니다.
- 틸드 영상 영역은 작은 창과 모바일에서 화면 전체 너비에 맞춘 16:9 비율을 사용합니다. 영상과 포스터는 `object-contain object-center`로 원본 전체를 표시해 좌우가 잘리지 않고, 아래 소개 문구가 바로 이어집니다. 폭 1024px 이상이면서 화면비가 16:9 이상인 넓은 데스크톱은 기존 `100dvh`·`object-cover` 화면을 유지합니다. 이 경우 너비는 원본에 맞고 세로 일부만 크롭될 수 있습니다. 창 크기 변경·기기 회전에도 CSS로 즉시 전환하며, 원본 영상 파일·자동 반복 재생·일시정지 버튼·영문 메뉴는 유지합니다.
- 가로 1023px 이하에서는 `public/videos/tilde/encounters-mobile.mp4`, 그 밖에는 `public/videos/tilde/encounters.mp4`를 불러오며, 두 파일 모두 동일한 1920×1080·30fps 영상입니다. 연결본은 주로 720p인 원본을 확대해 인코딩한 파일입니다. 8번 구름에는 앞서 승인된 2160×1080 AI 업스케일 결과를 사용하고 16:9로 크롭합니다. 파일은 재생 시작 시 한 번 선택해 기기를 회전해도 장면이 이어집니다. 공통 포스터는 `public/images/tilde/photography/encounters-poster.webp`이며 URL의 버전 값으로 이전 파일의 브라우저 캐시를 구분합니다.
- 기본은 소리 없는 자동 반복 재생입니다. 왼쪽 아래 `TildeFilmControl`의 작은 반투명 원형 버튼으로 일시정지하고 현재 위치에서 이어 재생할 수 있습니다. 버튼은 첫 화면 안에 맞춘 영상 영역의 왼쪽 아래에 배치합니다. 영상 영역이 화면 밖으로 나가면 버튼도 함께 사라지며 본문을 가리지 않습니다. 모바일 하단 안전 영역을 고려하고, 시각적 원은 32~36px, 클릭 영역은 44px을 유지합니다. 실제 재생 상태에 맞춰 아이콘과 접근성 이름을 갱신합니다. 동작 줄이기를 설정하면 포스터를 표시하고 자동 재생하지 않되, 사용자가 버튼을 눌러 직접 재생할 수 있습니다. 사용자가 일시정지한 상태는 화면 크기를 바꿔도 유지합니다.

- `ScrollReveal`: 화면 진입 시 콘텐츠를 한 번 부드럽게 표시합니다. 틸드에서는 이를 감싼 `TildeReveal`을 영상 아래 소개 문구·타원과 하단 이야기의 문구·사진에 적용합니다. 처음부터 화면에 있는 콘텐츠, JavaScript를 실행하지 않거나 `IntersectionObserver`를 지원하지 않는 환경에서는 본문을 숨기지 않습니다. 동작 줄이기 설정에서는 이동과 전환 없이 표시합니다.
- `ScrollScene`: `requestAnimationFrame`으로 스크롤 진행률을 CSS 변수에 전달해 휴대폰과 사진을 천천히 이동합니다. React 상태를 매 프레임 갱신하지 않으며 화면 밖에서는 업데이트를 줄입니다.
- 넓고 충분히 높은 화면에서는 어썸의 초대장 장면을 sticky 방식으로 보여줍니다. 모바일·좁은 화면·낮은 화면에서는 자연스러운 세로 배치로 전환합니다. 현재 틸드 하단은 일반 문서 흐름으로 이어지며, 보관된 이전 활동 장면의 sticky 효과는 실행하지 않습니다.
- `prefers-reduced-motion: reduce`에서는 연속 이동과 전환 효과를 줄이고 콘텐츠를 표시합니다.
- 서비스 본문은 Server Component를 기본으로 하며 영상 재생과 스크롤 제어에 Client Component를 사용합니다. 현재 틸드의 이야기 섹션은 별도 상태나 앱 설정 변경 기능을 갖지 않습니다.

## 스타일 관리

회사·틸드·어썸의 상단은 `Header`와 `FloatingBar`가 제공하는 `COMPANY / TILDE / AWESOME` 메뉴로 통일합니다. 메뉴는 첫 화면에만 겹치는 absolute 배치이며 활성 경로에 얇은 밑줄을 표시합니다. `data-immersive-page`가 있는 라우트에서는 흰색, 문의·약관에서는 어두운 색을 사용합니다. 스크롤바는 얇은 세이지 색으로 전역 적용하며 키보드 스크롤과 기본 스크롤 동작은 유지합니다.

회사 페이지는 화면 전체 너비와 최소 `100dvh`의 포레스트 첫 화면, 크림색 브랜드 관점, 두 서비스 사진 패널로 구성합니다. 어썸은 네이비 첫 화면과 크림색 편지·신뢰 영역을 전체 폭으로 이어가며, 기존 앱 미리보기·서비스 설명·출시 준비 안내와 라우트를 유지합니다. 틸드는 따뜻한 흰색 `#FDFBF8` 본문 배경 위에 기존 영상과 소개, 세 가지 이야기 섹션을 이어갑니다. 이 배경은 틸드 라우트의 본문과 페이지 바깥 배경에만 적용합니다. 이야기 섹션에 넓은 색 띠는 두지 않으며 지정 문구 뒤에는 장식 타원을 표시합니다. 공통 메뉴·푸터와 다른 라우트의 배경은 유지합니다. 공통 본문 여백은 해당 라우트의 래퍼에서만 상쇄하므로 문의·약관의 가독성 여백은 유지됩니다.

일반 레이아웃·타이포그래피·색상·반응형 배치는 Tailwind를 우선합니다. 공통 제목·휴대폰 프레임·출시 안내와 일반 콘텐츠 영역은 Tailwind 클래스로 작성했습니다.

CSS Modules는 브랜드별 겹친 비주얼, sticky 스크롤 장면, 원본 앱 시안의 세밀한 내부 디자인에 사용합니다. 컴포넌트 옆에 두고 선택자와 속성을 읽기 쉬운 여러 줄 형식으로 작성합니다. Prettier 설정과 실행 방법은 [개발 및 배포 가이드](development-and-deployment.md)를 참고합니다.

기본 소개 문구는 각 서비스의 `_data/service.ts`, 틸드 하단의 이야기 문구와 사진 연결 정보는 `tilde/_data/stories.ts`, 첫 갤러리의 배치 정보는 `tilde/_data/conversation-gallery.ts`에서 관리합니다. 실제 사진과 로고는 `public/images/<서비스>/`에 둡니다. 공통 화면 구조와 로컬 자산은 [README](../README.md#폴더-구조)를 참고합니다.
