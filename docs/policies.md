# 틸드·어썸 약관 작성 가이드

2026-11-03 기준으로 공식 법령·가이드와 제공된 서비스 기획서를 참고하여 작성한 **출시 전 검토용 초안**입니다. 법률 검토를 마친 최종 문서나 모든 의무의 이행 확인서가 아닙니다. 현재 홈페이지는 앱 가입·결제·위치정보 수집이나 신고 접수를 제공하지 않습니다.

## 푸터 항목과 적용 기준

‘모든 앱에 아래 문서 전부가 법적으로 필수’라고 보지 않습니다. 계약 조건, 처리방침 공개, 기능별 동의 및 안전 운영 기준을 구분하여 틸드·어썸에 필요한 공개 문서로 구성했습니다.

| 항목                    | 경로                 | 선정 근거와 적용 조건                                                                         |
| ----------------------- | -------------------- | --------------------------------------------------------------------------------------------- |
| 이용약관                | `/policy/terms/`     | 가입·이용계약의 기본 조건. 앱에서 계약 전에 제시·설명하고 동의를 받는 흐름 필요               |
| 개인정보 처리방침       | `/policy/privacy/`   | 개인정보 처리 시 법령에 맞게 수립·공개. 실제 홈페이지와 앱의 처리 내역을 구분                 |
| 위치기반서비스 이용약관 | `/policy/location/`  | 개인위치정보를 이용하는 기능을 제공할 때 검토·적용. 단순 지역 입력과 기기 위치 수집은 구분    |
| 유료서비스·환불정책     | `/policy/payment/`   | 유료 상품을 실제 판매할 때 가격·공급·청약철회·해지·정산 조건 안내                             |
| 커뮤니티·안전정책       | `/policy/operation/` | 사칭·사기·괴롭힘·성착취·무단 공개, 모임 안전 및 제재·이의제기 기준                            |
| 청소년보호정책          | `/policy/youth/`     | 성인 서비스의 연령 확인·유해정보 예방 원칙. 법정 보호책임자 지정 의무는 별도 요건에 따라 판단 |

기존 `/policy/brand/` 항목은 목록과 정적 생성 대상에서 제외했습니다. `/policy/`의 기본 항목은 여전히 이용약관입니다. 기존 `terms`, `privacy`, `location`, `operation`, `rights` 경로를 유지하고 `payment`, `youth`를 추가했습니다.

## 서비스 기획 반영 범위

- 틸드: 만 19세 이상 가입, 만남·번개모임·동아리, 만남 ON/OFF, 유료 재화·회원권 검토를 반영했습니다. 만남 OFF를 탈퇴·모든 정보 삭제·구독 해지와 동일시하지 않습니다. 주소록 자동 수집은 기획상 전제로 하지 않습니다.
- 어썸: 성인 대상 프로필 확인, 편지, 상호 동의, 일정·출발 지역과 초대장, 연락처별 노출 제외, 심사·회원권·만남권의 상품 구분을 반영했습니다. 확인 배지가 모든 신원·안전·자산을 보증한다고 쓰지 않았습니다.
- 틸드의 만 19세 기준은 기획서에 명시되어 있습니다. 어썸은 성인 대상 방향을 바탕으로 만 19세 이상을 초안 기준으로 제안한 것이므로 최종 확정이 필요합니다.
- 기획서의 임시 법인명, 확정 전 가격·자산 기준·기간·차감식·노쇼 보상액을 실제 조건으로 공개하지 않았습니다.
- 원본 기획서의 자동 삭제·대화 종료 시간이 출시 조건으로 확정되지 않았으므로 기간을 임의로 확정하지 않았습니다.

## 푸터와 별도로 필요한 동의 흐름

개인정보 처리방침은 처리 현황을 공개하는 문서이며 수집·이용 동의서 자체가 아닙니다. 문서 열람이나 이용약관 동의만으로 모든 개인정보 처리에 동의한 것으로 보지 않습니다.

- 가입 시 이용약관을 제시하고, 개인정보 항목별 처리 근거를 구분합니다. 동의를 근거로 처리하는 경우 목적·항목·보유기간·거부권과 영향을 별도로 고지합니다.
- 민감정보를 입력·추론·추천에 사용할 경우 필요성·공개 범위와 별도 동의 등 적법한 근거를 검토합니다. 종교·건강·성생활 등의 정보를 일반 프로필에 숨겨 포괄 처리하지 않습니다.
- 개인위치정보 이용·제공의 법정 동의와 운영체제 권한은 별개입니다. 위치정보 사업 관련 신고·등록, 확인자료 보존과 담당자 공개 요건도 실제 사업 형태에 맞춰 검토합니다.
- 제3자 제공·국외이전·마케팅은 실제 방식과 법적 근거에 따라 안내·동의 절차를 구분합니다. 마케팅 수신을 필수 가입 조건으로 묶지 않습니다.
- 유료 상품의 중요한 조건은 푸터뿐 아니라 결제 직전에도 제시합니다. 디지털콘텐츠 청약철회 제한과 자동결제·가격 변경의 법정 고지·동의 요건을 구현해야 합니다.

## 정식 공개 전 확정 사항

1. 계약 당사자와 개인정보처리자의 정식 상호·대표자·주소·사업자 정보 및 실제 고객센터를 확정합니다. 통신판매를 할 경우 신고·표시 등 적용 의무를 따로 검토합니다.
2. 개인정보·위치정보·청소년 보호·권리침해 요청 담당부서와 실제 연락처를 공개합니다. 현재 문의 페이지는 접수 창구가 아니므로 신고가 접수된 것처럼 안내하지 않습니다.
3. 서비스·목적별 실제 수집 항목, 필수·선택 여부, 법적 근거·보유기간·파기 시점과 백업 처리 일정을 확정합니다.
4. 본인확인·결제·알림·저장소·분석·호스팅의 업체 목록, 위탁 업무, 제3자 제공·국외이전 내역을 실제 계약과 설정으로 확인합니다. ‘없음’을 임의로 기재하지 않습니다.
5. 위치정보 수집 방식·범위·주기와 원본 좌표의 보유기간을 정합니다. 확인자료 6개월은 초안 운영안이며 법정 요건 검토 후 확정합니다. 원본 위치의 일괄 장기 저장 근거로 사용하지 않습니다.
6. 심사 개시·거절, 이용권 차감·복구·만료·이월, 구독 해지와 모임 취소·노쇼별 계산식을 확정합니다. 포인트 복구로 법정 현금 환불을 대체하지 않습니다.
7. 조항과 실제 기능의 일치 여부를 법률 검토한 뒤 시행일·개정 이력·고지 수단을 정하고 초안 상태를 변경합니다. 홈페이지를 방문했다는 이유로 가입 동의를 받은 것으로 처리하지 않습니다.

## 소스 구조

```text
src/data/policies.ts                       # 공통 푸터·구분 메뉴·SSG 경로 목록
src/app/policy/
├── _data/
│   ├── documents/
│   │   ├── terms.ts
│   │   ├── privacy.ts
│   │   ├── location.ts
│   │   ├── payment.ts
│   │   ├── operation.ts
│   │   ├── youth.ts
│   │   └── rights.ts
│   ├── policy-content.ts                  # 문서별 본문 연결
│   └── policy-sources.ts                  # 공식 출처·초안 상태·기준일
├── _components/
│   ├── intro/                             # 페이지 안내
│   ├── navigation/                        # 약관 구분과 상세 경로 이동
│   ├── article/                           # 선택한 문서 조합
│   ├── notice/                            # 초안 상태·확정 전 항목
│   ├── contents/                          # 조항별 목차
│   ├── section/                           # 조항·문단·목록 표시
│   ├── references/                        # 공식 출처
│   └── view/                              # 통합 약관 화면 조합
├── _lib/get-policy.ts
└── _types/policy.ts
```

새 문서를 추가할 때는 공통 목록과 본문 연결을 함께 갱신합니다. 푸터는 `src/components/layout/footer/`에서 같은 목록을 사용합니다. 문서별 코드는 라우트 전용이므로 공통 `components/`로 이동하지 않습니다.

이번 변경에서는 사용자 지시에 따라 린트·타입검사·빌드·테스트를 실행하지 않았습니다.
